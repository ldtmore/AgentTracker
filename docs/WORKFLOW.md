# AgentTrackerIsland 协作工作流(多 Agent 接力开发规程)

> 本文件定义本项目的**标准执行流程**与**交接规则**。
> 任何 AI Agent(或人类)参与本项目前必须先读本文件,再读 [AGENTS.md](../AGENTS.md)。
> 状态:已生效 | 制定:2026-09-16,与项目所有者共同确认

## 总流程:三阶段

```
阶段0            阶段1            阶段2                阶段3
交接基础设施  →  需求梳理     →   调研与方案回填    →  逐项实施
(半天)          (逐项确认)       (不造轮子)          (多Agent接力)
                     │                                   │
                     └── 调研结果可回填修正需求 ──────────┘
                         (需求冻结前允许循环一次)
```

## 阶段 0:交接基础设施(一次性)

建立项目文档体系(即本文件所在体系),确保"进度与决策"全部落盘,不依赖任何对话记忆。

## 阶段 1:需求梳理

- 由当前 Agent 起草需求框架,**与项目所有者逐项确认**(分块提问,一次只收敛一个维度)
- 需求维度清单:
  1. 项目边界与范围(做什么/明确不做什么)
  2. 目标用户与核心使用场景
  3. 功能清单(状态监控 / 用量统计 / 其他小功能)与优先级
  4. Agent 支持范围(Claude Code、Codex、Trae……哪些进 M0/M1/M2)
  5. 供应商与额度支持范围(GLM、Anthropic 官方……)
  6. UI 形态(灵动岛 / 悬浮球 / 报表页)与交互细节
  7. 视觉风格与配色方案
  8. 非功能需求(内存/包体/启动速度等"轻量"量化指标)
  9. 技术栈倾向(此阶段仅定倾向,阶段 2 调研后定稿)
  10. 分发与安装方式
- 产出:`docs/00-REQUIREMENTS.md`(草案 v0.9)

## 阶段 2:调研与方案回填

- **目的:不造轮子。** 按需求逐项检索公开渠道(GitHub / 官方文档 / 社区),
  将每个功能点归入三类:
  - 🟢 直接依赖:现成库/插件/crate,直接引入
  - 🟡 借鉴实现:有开源参考,借设计与关键代码思路,自己实现
  - 🔴 必须自研:市面上没有,写清实现要点
- 调研结论**回填修正需求**(若发现现成方案改变了某项需求的合理形态,回阶段 1 确认一次)
- 产出:
  - `docs/01-RESEARCH.md`(调研报告:依赖/借鉴/自研三分清单)
  - `00-REQUIREMENTS.md` 冻结为 v1.0
  - `docs/02-DESIGN.md`(实现方案:架构、数据模型、模块划分)
  - `docs/03-TASKS.md`(任务看板:原子任务,每个任务带验收标准)

## 阶段 3:逐项实施(多 Agent 接力)

**交接铁律(每个参与 Agent 必须遵守):**

1. 开工前必读顺序:`AGENTS.md → WORKFLOW.md → HANDOFF.md → 03-TASKS.md`
2. 只做看板上分配/认领的任务,**不做看板外的事**(发现新需求→记录到看板"待议",不擅自扩scope)
3. 每个任务交付 = 代码(含中文注释)+ 通过验收标准 + **同步更新看板状态与 HANDOFF.md**
4. 任务粒度以"单次会话可完成并可验证"为上限;做不完的任务,把已完成部分、未完成部分、
   踩过的坑如实更新到 HANDOFF.md 后再结束会话——**禁止只留半成品不写说明**
5. 里程碑暂停点(数据正确性验证、首个可用版)须由项目所有者验收后再继续

## 构建打包纪律(2026-09-17 所有者制定,对所有参与者生效)

**构建打包(release 构建 / 便携 zip / 安装包)是整个项目的最后一步工作**,仅当以下
条件同时满足、且所有者明确提出时才执行:

1. 功能已全部完善,需求已全部实现;
2. 代码测试无缺陷,验收已通过;
3. **所有者明确说明"项目需要打包构建向外正式发布"**。

其余任何阶段(需求开发 / 调试 / 验证 / 优化打磨)一律:**本机调试开发 + GitHub
代码提交,不做任何构建打包操作**。任何 Agent 会话不得主动发起 `tauri build` /
release 打包;`cargo test`、`npm run build`(类型检查)等**验证性构建不受此限**。

> 当前阶段定位(2026-09-17):需求开发与验证阶段——M0 刚收尾、M1 尚未开始,
> 众多 bug 与细节(功能/统计/展示)由所有者暂时搁置、待后续统一优化修改。
> 日常迭代一律不触发打包;打包动作只认所有者的明确发布指令。
