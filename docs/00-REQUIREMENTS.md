# AgentTracker 需求规格书

> 状态:**v1.0 已冻结**(2026-09-16,阶段 2 调研回填完成——调研未发现需修正的需求项,10 维度原样冻结)
> 冻结后变更须走"待议→所有者确认→记录变更"流程 | 实现方案:[02-DESIGN.md](02-DESIGN.md)

## 维度① 项目边界与核心场景 ✅ 已确认(2026-09-16)

### 已确认(来自定位讨论,不可动摇)

- ✅ 定位:主流 AI Agent 的**旁路观测工具**——只看,不碰;装不装它,Agent 与用户工作流零影响(详见 [AGENTS.md](../AGENTS.md) 五条红线)
- ✅ 诞生背景:项目所有者曾是 CC Switch 用户,只要其统计能力、不要其代理与全家桶;需要一个轻量替代

### 确认结果

- ✅ **驱动方式**:开发阶段自用(Dogfood),开发完整后可能发布 GitHub 公共仓库;不做产品化运营(官网/宣传/多语言不做)
- ✅ **平台边界**:Windows 首发,代码保留跨平台可能性(Tauri),但不承诺 macOS/Linux 版
- ✅ **M0 Agent 范围**:Claude Code CLI + **ZCode**(所有者当前主力即此二者)
- ✅ **M0 供应商范围**:GLM Coding Plan
- ✅ **投入预期**:轻量自用+开源,AI Agent 开发为主+所有者把关;代码质量保持产品级,避免过度设计
- 📌 **新增调研点(阶段2)**:ZCode 的本地数据可用性——转录文件位置/格式、hooks 机制、token 记录、额度查询方式(可在所有者本机直接勘察)

## 维度② 功能清单与优先级 ✅ 已确认(2026-09-16)

### 已确认的方向

- ✅ 三大功能域:①Agent 工作状态实时监控 ②大模型用量统计与查询 ③其他相关小功能(后置)
- ✅ 状态语义倾向:🟢呼吸=工作中 / 🟢常亮=完成·空闲 / 🟡=等待输入 / 🔴=出错 / 灰=离线(待视觉阶段终审)

### 确认结果(M0 功能切法)

- ✅ **多会话**:M0 支持同 Agent 多会话并行显示(展开面板每会话一张卡片;收缩态显示聚合状态——任一会话出错岛即红)
- ✅ **报表页**:独立报表页放 M1;M0 只做灵动岛内展示(会话卡片含本会话 token,额度条含百分比+重置倒计时)
- ✅ **点击跳转**:进 M0——点击会话卡片激活对应终端/IDE 窗口(窗口级定位,不承诺标签页/tmux 级精度)
- ✅ **额度提醒**:进 M0,静默式——额度达阈值(默认 80%/95%,可配)岛变色;声音等打扰性通知一律默认关(opt-in)
- ✅ **悬停球模式**:双形态切换按原始构想保留(具体节奏在维度⑤确认)

## 维度③ Agent 支持范围与节奏 ✅ 已确认(2026-09-16)

- ✅ **M0**:Claude Code CLI + ZCode(所有者当前主力)
- ✅ **M1+ 愿景池**(按社区呼声与接入成本排期,阶段 2 调研分层):
  Codex CLI、Gemini CLI、Trae、Qoder、WorkBuddy、Cursor、Windsurf、Hermes、OpenClaw
- 📌 注:IDE 型(Trae/Qoder/Cursor/Windsurf)无标准 hooks,接入方案需阶段 2 专项调研
- 📌 **新增调研点(阶段2)**:ZCode 本机数据勘察(转录/hooks/token 记录/额度接口)

## 维度④ 供应商与额度支持范围 ✅ 已确认(2026-09-16)

- ✅ **M0**:GLM Coding Plan(5h/周积分窗口,Monitor API 已验证可查)
- ✅ **M1+ 愿景池**:Anthropic 官方订阅(OAuth)、Kimi(月之暗面)、DeepSeek、OpenAI 等全球主流供应商
- ✅ **纯计费供应商**:提供"仅 token 统计"降级视图(不显示额度百分比)

## 维度⑤ UI 形态与交互 ✅ 已确认(2026-09-16)

- ✅ **双形态规划**:灵动岛(M0);M1 视情况增加悬浮球与**任务栏**形态(与岛复用同一套数据/组件)
- ✅ **岛停靠**:默认屏幕顶部居中,可拖拽改位并记忆
- ✅ **展开面板**:hover 展开(不抢焦点),每会话一张卡片(状态/模型/项目名/本会话 token),额度区显示 5h/周百分比条+重置倒计时
- ✅ **点击跳转**:点击会话卡片激活对应终端/IDE 窗口(窗口级)
- ✅ **报表页**(M1):独立窗口形态(岛内不放报表)

## 维度⑥ 视觉风格与配色 ✅ 已确认(2026-09-16)

- ✅ **整体风格**:M0 交付暗黑科技主题(深色+半透明毛玻璃+彩色状态灯);M1 视情况增加深/浅双主题,跟随系统主题变化,设置项允许用户自选
- ✅ **状态视觉语言**:简约灯效+图标(状态灯呼吸/常亮/闪烁 + Agent 徽标),不做像素宠物类重美术资产
- 📌 具体色板(状态色值、背景透明度、毛玻璃参数)在阶段 2 调研 Windows Acrylic/Mica 效果实现方式后,随 UI 原型一并终审

## 维度⑦ 非功能需求("轻量"的量化) ✅ 已确认(2026-09-16)

- ✅ **性能指标(验收项)**:常驻内存 ≤100MB;安装包 ≤15MB;冷启动 ≤2s
- ✅ **常驻方式**:系统托盘常驻(观测工具须活着才能观测);开机自启为设置项,**默认关**(用户自选)
- ✅ **数据保留**:默认**全量保留**;设置项提供清理周期选择:
  永不清理(默认)/ 3 年 / 2 年 / 1 年 / 6 个月 / 3 个月 / 1 个月 / 1 周
- ✅ 零遥测、零联网激活(红线延伸:额度查询是唯一对外请求)

## 维度⑧ 技术栈与分发 🟡 倾向已定(阶段 2 定稿)

- 🟡 当前倾向:Tauri 2 + Rust + React/TS + SQLite(rusqlite);阶段 2 盘完轮子后定稿
- ✅ **M0 分发**:便携 zip(解压即用)+ 开发期 `tauri dev` 直跑;NSIS 安装包/winget 等发布渠道 M1 再做

## 维度⑨ 数据采集边界(红线的技术细化) ✅ 已确认(2026-09-16)

- ✅ **三链路架构**:hooks 事件文件(增强档,向导可装卸)→ 转录文件监听(默认档,零配置)→ 进程枚举(兜底);层层降级,任何一层缺失主流程可用
- ✅ **hooks 事件文件协议**:桥脚本只 append 本地事件文件即退出,不连端口不找进程——主程序死活不影响 Agent
- ✅ 唯一对外请求 = 供应商额度查询(带超时、缓存、降级)
- 📌 hooks 注入/卸载的实现细节 → 阶段 2 调研后定

## 维度⑩ 里程碑与验收 ✅ 已批准(2026-09-16)

### M0(首个可用版)

**范围**:Claude Code + Zcode 双 Agent 监控 · GLM 额度 · 灵动岛(多会话卡片/状态灯/点击跳转/静默额度提醒)· SQLite 全量统计 · 便携 zip

**验收标准**:

| # | 验收项 | 通过条件 |
|---|---|---|
| A1 | 状态正确性 | 工作中/等待输入/出错三场景岛显示正确;看门狗生效不卡状态 |
| A2 | 数据正确性 | 本机 token 统计与 ccusage 对账一致(差异仅统计口径) |
| A3 | 额度正确性 | GLM 5h/周百分比与官网用量页一致,重置倒计时准确 |
| A4 | 跳转 | 点击会话卡片激活对应终端/IDE 窗口 |
| A5 | 性能 | 常驻内存 ≤100MB,冷启动 ≤2s |
| A6 | 红线回归 | 退出/卸载本工具后,Claude Code 与 ZCode 运行无任何报错与延迟感知 |
| A7 | Dogfood | 所有者日常自用 ≥1 周,不再需要手动查额度 |

### M1(完整自用版)

悬浮球/任务栏形态(视情况) · 深浅双主题跟随系统+设置自选 · 独立报表页(趋势/热力图/按模型·供应商·时间聚合)· NSIS 安装包 · Anthropic 官方订阅额度 · 新增 Agent(按阶段 2 调研的接入成本排序,Codex CLI 预期最优先)

### M2(开源发布版)

Trae/IDE 型 Agent 接入 · Kimi/DeepSeek 等供应商 · GitHub 公共仓库发布 · 社区呼声功能
